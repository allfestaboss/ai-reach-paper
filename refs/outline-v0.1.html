単一ドメインでは
原理的に取り出せない量を、3つ持っている。

この論文の主張は「AIが何点取ったか」ではない。8業種を同じ設計で並べたときにだけ見える量がある、というのが中身。 資料を渡す効果の符号が業種で反転すること、点数が飽和してもコストは分離すること、 非決定性の大きさが業種で25%と74%に割れること。どれも1本のベンチからは出てこない。

01Introduction — 何が空いているか

1.1
材料あり
議論に実測が無い

「AIに専門職の仕事が奪われるか」の議論は大量にあるが、根拠として実測を出したものが見当たらない。 税務では「AIに判断は危険」と書いた記事が多数あるのに、出てくるのは USCPA の点数と OCR のベンダー自己申告だけだった。

1.2
材料あり
既存ベンチは2種類しかない
  • 試験問題型 — JMMLU / JMED-LLM / IgakuQA119。選択肢を選ばせる。成果物を作らせない
  • 単一ドメイン型 — ATLAS（HS分類）、BIM-Edit（IFC編集）、AECV-Bench（図面理解）。ドメイン内で閉じる

本研究の位置は実務の成果物生成 × 業界横断 × 同一設計。

02Design — 4つの設計原則

2.1
材料あり
正解に自作を混ぜない（外部性の3段階）
  • 第1段階 — 参照解だけ外部（kanzei：税関の回答）
  • 第2段階 — 手順も外部（sekisan / doboku：公的基準）
  • 第3段階 — 入力も外部（jiban：国交省の実測ボーリング × 示方書 × 機械的に通した結果）

自作した参照解は、較正でも敵対テストでも検査できない。「参照解を真とする前提」の上に検査が立つため。

2.2
材料あり
点数を出す前に、採点器を敵対テストで検証する

参照解を意図的に壊した答案を作り、採点器が落とすことを確認する。決め手になったのは 平成24年版の式で解いた答案で、桁も式の形もそれらしく、許容の緩い採点器は満点で通す。 着手時に著者自身が踏みかけたのがこれである。

2.3
材料あり
導けない値は与件に分離する

jiban では γt・地下水位・khgL をタスクの与件として明示した。参照解に決めさせると、 そこに著者の裁量が入り 2.1 が崩れる。

2.4
材料あり
腕を束ねない

A / B / C / D を分けないと軸を取り違える。sekisan で B→D を束ねていたのが最初の失敗だった。

03Findings — 横断でしか見えない3つ

ここが論文の芯。いずれも1本のベンチからは原理的に出てこない。

所見 1
資料を渡す効果は、業種によって符号が反転する。
業種資料を渡すと実測
土木CAD（doboku）劇的に効く25 → 97 点（形式の説明のみ）
積算（sekisan）効く条文が最大の因子
通関（kanzei）効かない・悪化するarmB < armA。81万→440万字で 0 件変化

通関では61件を分解すると、資料に関係なく解ける34件／どれだけ渡しても解けない15件／動くのは12件だけ。 「権威ある資料を渡せば正確になる」は業種に依存する仮説であって、一般則ではない。

所見 2
点数は飽和する。コストは飽和しない。
業種点数コスト
液状化（jiban）B = C = D = 100（課題を6倍にしても）armB は armC の 約2.6倍のトークン
幾何公差（kikai）armC が 6/6、armB が 5/61,053,066 → 216,591（約4.9倍差）
BIM（bim）armC 255/255、armB 235/255371,572 → 98,901（約3.8倍差）

コード実行が買っているのは正確さではなく単価である。 点数だけを報告するベンチは、この差を構造的に見落とす。

所見 3
同じ問いに同じ答えが返らない。その大きさが業種で割れる。
  • 通関 — 同一条件5回で全回一致は 46/61。25% が毎回ちがう
  • 税務 — 74% の事案で答えが毎回ちがう。ただし引用の的中数は 124本±1 で不動。 52本が当たったり外れたりして合計だけ釣り合っている
  • 積算 — S005 は5回とも1文字違わず同じ

「規則を渡せば決定論的になる」も業種に依る。 同じ問いに同じ答えが返ることが要件の場面（税務・監査）では、精度以前の問題になる。

04副次的な所見（節を立てるか、まとめて1節か）

  • 検査器は答えをほとんど変えない。 通関では armD が2回とも税番を1件も変えず、armC を下回った（39 対 42、ただしノイズ範囲）
  • 暗記は検出されなかった。 カットオフ前後で類を揃えると差は armA −0.008 / armB +0.005。素の差は逆向き。公開ベンチの汚染は、少なくともこの形では心配しなくてよい
  • RAG が外すのは「拾えていない」側。 渡した候補に正解が入っていれば 86% 拾うが、入っていない正解は 48%。候補を20→40に倍増しても +2.2ポイント
  • 腕が参照解の誤りを見つける。 jiban T002 第1回で4件（Fc の取りこぼし／D50・D10 の存在／PL の孔底外挿／検査器の形式不備）。うち PL の外挿は、780312 の PL の60%がボーリングしていない深さから出ていた

05Threats to validity — 先に書く

隠さないほうが強い
  • n が小さい。 n=1〜5。通関の n=5 で SD 1.10、42 は範囲の上端だった。armC 42 と armD 39 の差はノイズと自分で書いている
  • 実施者が1人。 課題設計・参照解・採点器・実行がすべて同一人物
  • 腕はモデル比較ではない。 同一基盤モデルの足回り違いを測っている
  • 出題側の欠陥が通算15件、うち14件が事実だった。 関税率表のパーサは4回直した。1件は作業ミス（生成物を2つ持ち片方だけ更新した）
  • 統制の不備を1件やった。 n=5 の作業場を共有スクラッチパッドの下に並べ、前回の解答が到達可能な位置にあった。汚染は答えが揃う向きに働くので 25% は下限
  • 一部ドメインには規模で大きく上回る先行研究がある。 ATLAS は税関裁決 18,731 件

最後から2つ目は、書けば方法論への貢献になる。ベンチの統制がどこで破れるかの具体例は、あまり公表されていない。

06足りないもの — 書く前に埋める

A

腕の統一が取れていない

kikai と bim は armB・armC のみで、A と D が無い。cad / sekisan / doboku / zeimu は D が無い。 「同じ物差し」を主張するなら、せめて B と C は全8本に揃える必要がある。 現状で全8本に共通するのは B と C だけなので、横断の比較は B/C に限定して書くのが誠実。

B
未
コストが全本で取れていない

所見2は jiban / kikai / bim の3本で立っている。残り5本のコスト実測があると主張が一段強くなる。 `cost.json` の仕組みは既にあるので、走らせ直すだけ。

C
未
反復が2本しかない

所見3は kanzei（n=5）と zeimu でしか測っていない。 非決定性が業種で割れるという主張には、あと1〜2業種の n=5 がほしい。
